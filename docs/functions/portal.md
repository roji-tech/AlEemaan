# Parent and student portal — Functions (services, libraries, API routes)

The portal's own session (a signed, stateless cookie), sign-in, and the read and write routes behind `/portal`. None of it uses the school app's `withAuth` session.

## `src/lib/portal/`

The parent and student portal's own sign-in and data access, separate from staff accounts (no `User` row, no `Session` row).

| File | Description |
| --- | --- |
| `auth.ts` | The portal's stateless session: `signPortalSession` and `verifyPortalSession` (HMAC-SHA256 over a base64url JSON payload of `primaryStudentId`, `allowedStudentIds`, guardian contacts, `issuedAt`, `expiresAt`; constant-time compare, payload rebuilt field by field, 7 days), the cookie helpers (`PORTAL_COOKIE_NAME`, `setPortalCookie`, `clearPortalCookie`, `getPortalSession`), and the sign-in matchers `matchesDateOfBirth` (`YYYY-MM-DD`, `DD/MM/YYYY`, `DD-MM-YYYY`), `matchesPhone` (full number, national digits, or the last 4 or more digits) and `findSiblingStudentIds` (active pupils sharing the guardian phone or email, in any branch). No database row exists, so signing out only clears the cookie. |
| `secret.ts` | `portalSecret`, `portalSecretProblem`, `PortalSecretError`, `PORTAL_SECRET_ENV`: the cookie signing key, read only from `SESSION_SECRET` (at least 32 characters, at least 10 distinct, not the retired published default; `AUTH_SECRET` is no longer read). No fallback: signing or verifying without a valid secret throws, and `src/instrumentation-node.ts` exits the process at start-up. |
| `service.ts` | `authenticatePortalViaToken` (a `GuardianLinkToken` by SHA-256 hash, unexpired; it stamps `usedAt` but never rejects a used link) and `authenticatePortalViaAdmission` (admission number matched case-insensitively and exactly with raw SQL, active pupils only, at most 5 candidates; secret = date of birth, guardian phone or guardian email; every failure returns `PORTAL_SIGNIN_FAILED`), both returning the signed cookie value with the pupil and siblings. Also `resolvePortalSessionData` and the readers `getStudentPortalOverview`, `getStudentPortalResults`, `getStudentPortalInvoices`, `getStudentPortalLms`, plus `submitPortalAssignment`, `attemptPortalQuiz` and `PortalLmsError`; each checks the pupil is in `allowedStudentIds` first. |

## API routes: Parent and student portal (`/api/v1/portal/`)

The portal has its own sign-in and does not use staff sessions or `withAuth`: `session` issues an HMAC-signed cookie (`aleemaan.portal-session`, `__Host-` prefixed over https, 7 days) and every other route reads it with `getPortalSession`, answers 401 without a valid one and 403 when the `[studentId]` in the URL is not in the session's `allowedStudentIds` (the pupil plus siblings sharing a guardian phone or email); only the sign-in is rate limited.

| Method | Route | File | Who | Description |
| --- | --- | --- | --- | --- |
| DELETE, GET, POST | `/api/v1/portal/session` | `portal/session/route.ts` | Anyone (public); GET needs the portal cookie | POST signs in with `{ token }` (a guardian link token) or `{ admissionNo, secret }` (date of birth, guardian phone or guardian email); input is length-bounded and control or bidirectional characters are refused. CSRF, then 30 per IP and, for the admission-number form, also 5 per IP plus admission number and 10 per admission number per window, all refunded on a correct sign-in; a bad body is 400 and a failed sign-in 401 (every admission-number failure carries the same `PORTAL_SIGNIN_FAILED` text). Sets the cookie and returns `{ student, siblingStudents }`. GET returns `{ session, students }` or 401. DELETE (CSRF-checked) only clears the cookie: nothing is revoked server-side. |
| POST | `/api/v1/portal/students/[studentId]/assignments/[assignmentId]/submission` | `portal/students/[studentId]/assignments/[assignmentId]/submission/route.ts` | Portal session, pupils in the session only | A pupil (or linked guardian) hands in coursework. CSRF and portal cookie; body checked by `submitAssignmentSchema` (text and/or attachments). `submitPortalAssignment` takes the branch and class from the pupil's active enrolment: 404 for an assignment outside it, 400 once the work is `GRADED` or when the deadline passed without `allowLate`; a later hand-in replaces an earlier one. 201 `{ status, submittedAt }`. |
| GET | `/api/v1/portal/students/[studentId]/invoices` | `portal/students/[studentId]/invoices/route.ts` | Portal session, pupils in the session only | `{ invoices }`: the pupil's non-cancelled invoices with period and session, every payment on them (any status, newest first) and the discounts. Read-only: no payment can be started from here. |
| GET | `/api/v1/portal/students/[studentId]/lms` | `portal/students/[studentId]/lms/route.ts` | Portal session, pupils in the session only | The pupil's published `assignments` (with their own submission and a `closed` flag), `quizzes` (questions without the answer key, plus the last attempt) and `materials`, for the branch and class group of their active enrolment. Empty lists when the pupil has no class. |
| GET | `/api/v1/portal/students/[studentId]/overview` | `portal/students/[studentId]/overview/route.ts` | Portal session, pupils in the session only | The pupil's record with active enrolment, attendance counts and percentage (late counts as present; 100 when nothing is recorded) with the last 10 records, a fees summary over non-cancelled invoices, and the 5 latest published announcements for their branch or the whole school. 404 for an archived or missing pupil. |
| POST | `/api/v1/portal/students/[studentId]/quizzes/[quizId]/attempt` | `portal/students/[studentId]/quizzes/[quizId]/attempt/route.ts` | Portal session, pupils in the session only | A pupil takes a quiz: `{ answers: [{ questionId, answer }] }`, CSRF and portal cookie. Graded on the server against the answer key; 201 `{ score, isPassed, totalPoints }`. Each call stores a new `QuizAttempt`: no attempt limit, no rate limit, and the quiz time limit is enforced only by the page's countdown. |
| GET | `/api/v1/portal/students/[studentId]/results` | `portal/students/[studentId]/results/route.ts` | Portal session, pupils in the session only | `{ reportCards }`, one per period, from results with status `PUBLISHED` or `LOCKED` (subject lines, remarks, total and average). When the approved global setting `block_unpaid_report_cards` is on and the pupil owes money it returns `reportCards: []`, `blockedByUnpaidFees: true` and the balance instead. |
