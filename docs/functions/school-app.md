# School app — Functions (services, libraries, API routes)

The logic behind the signed-in school app: for each area, the library files under `src/lib/` (services that talk to the database, pure helpers, validation) followed by the
API routes under `src/app/api/v1/` that expose them. Every route is wrapped in `withAuth` or `withAuthGated` (see [`shared.md`](./shared.md)); the **Who** column says what the
guard allows, and `tests/unit/route-role-guard.spec.ts` fails if a route is added without an entry and a reason.

## `src/lib/academics/`

The academic domain of one branch: structure (classes, arms, subjects), sessions and terms, staff records and assignments, assessment schemes and grade scales, result entry and review, and report cards. The route decides who may act (`withBranch`); these modules enforce the rules of the data and write `AuditLog` or `ResultAudit` rows. Classes, arms, subjects, staff records, schemes and scales are archived, not deleted; only teaching assignments, subject offerings, DRAFT results and the parts or bands of an unlocked scheme or scale are really deleted. Rows are in file-name order.

| File | Description |
| --- | --- |
| `approver-scope.ts` | Where one member approves results (task 0039; Octalve Edu's ADR 0018): `approverScope(branchId, userId)` returns `{ approver, general, armIds }`, read only from `ResultApprovalScope` for an ACTIVE staff member holding `CAN_APPROVE_RESULTS` (no row means no results; a GENERAL row wins; an archived section covers nothing), `NOT_AN_APPROVER`, `covers(scope, classArmId)` (the arm a result was entered in is stored on it), `hasAnyScope`, `approverBranchIds(userId)`. An administrator of a branch is not asked. Slice 2a: under the branch setting `results.unsectionedClassApproval` = `ANY_SECTION_APPROVER` a person who holds a LIVE Section scope also reaches the classes of the branch that are in no section (`reachesUnsectioned`); under the default, or with a damaged value, it adds nothing, and an archived section widens nothing. |
| `approver-settings-http.ts` | The HTTP face of the sections and approver-scope settings (task 0039, slice 2b): the strict bodies (`createSectionBody`, `updateSectionBody`, `placeClassGroupBody`, `setScopesBody`, `unsectionedBody`, every write carrying `stepUp`), `settingsWriteLimited` (120 changes per window per person), `proofRefusal` (the fresh proof, asked after the cheap checks so a proof is not spent on a request that cannot work) and `approverSettingsFailure` (the one place that turns a refusal into a status, a stable `code` and words a person can act on). |
| `approver-settings.ts` | The superadmin's side of task 0039: `listSections` (live sections first, with their live classes, and the classes in none), `listApprovers` (active staff holding CAN_APPROVE_RESULTS with where they approve; none listed means they approve nothing), `createSection`, `updateSection` (rename, reorder, archive, restore; an archived section can only be restored; a live name is unique in the branch ignoring case), `placeClassGroup` and `setApproverScopes` (replaces a person's scopes as a set; an unchanged set writes nothing). Each write is ONE transaction with its `AuditLog` row (before and after); an id of another branch is, to this branch, one that does not exist. |
| `section-rules.ts` | The pure rules of sections and scopes: `cleanSectionName` (trimmed, collapsed, 1 to 80 characters, no control character), `normaliseScopeSet` (a repeat is one entry, fixed order, General cannot sit beside anything), `scopeKey`, `SCOPES_PER_PERSON_MAX` 100. |
| `unsectioned-approval.ts` | The branch setting `results.unsectionedClassApproval` (`GENERAL_OR_CLASS_ONLY` by default, or `ANY_SECTION_APPROVER`): `resolveUnsectioned` (anything that is not exactly one of the two names is the default, so a damaged row can only narrow), `getUnsectionedClassApproval(branchId)` and `setUnsectionedClassApproval(branchId, value, actorUserId)` (one `SettingValue` row per branch; every change in `SettingAudit` in the same transaction, `CHANGED_WIDENING` when the wider value is turned on; saving what is already there writes nothing). |
| `assessment.ts` | Assessment schemes and grade scales of one branch (Slice P1b): zod inputs `schemeInput`, `schemePatch`, `scaleInput`, `scalePatch`, the list, create, update, archive and `newSchemeVersion`/`newScaleVersion` functions, `makeDefaultScale`, `lockScheme`/`lockScale` and `WAEC_TEMPLATE`. One live scheme per branch and class (no class means the branch default); a branch's first scale becomes its default and the default cannot be archived. Writes take an advisory lock. |
| `report-card-export.ts` | `generateReportCardHtml(card, origin)` builds a self-contained A4 HTML report card (inline CSS, print button, verification links) and `downloadReportCardHtml` saves it as `ReportCard_<name>_<term>.html` (browser only). Unlike the on-screen `ReportCard` it fills an empty remark with a fixed sentence ("Satisfactory academic performance." and "Promoted/Advanced to next academic term.") and always draws signature boxes, ignoring `card.layout`. |
| `report-card-rules.ts` | Pure arithmetic of a report card, in hundredths of a percent: `percentHundredths`, `averageHundredths` (mean of the subject percentages), `rankAverages` (competition ranking: ties share a position and the next is skipped) and `publicName` ("Amina Yusuf" becomes "Amina Y."). |
| `report-card.ts` | The report card, computed and never stored: `getReportCard` (PUBLISHED and LOCKED results, or all with `includeUnpublished`; totals, average, position in the arm, remarks, legend, branch layout), `saveRemarks` (500 characters each; 409 once a result of the term is published), `verifyToken` (what the public verification page may say: genuine or not, school, branch, class, term, and name, subject, marks or grade as the branch's config allows), `reportCardVisibleTo` (staff always; others blocked by unpaid fees when `block_unpaid_report_cards` is on), `cardQuery`, `remarksInput`, `studentBranch`. |
| `results-workflow.ts` | The result review state machine (Slice P2b): `transitionResults` runs `submit`, `return`, `approve`, `revert`, `publish`, `lock`, `unlock` over up to 500 results, all or nothing, rows locked `FOR UPDATE`, one `ResultAudit` row each. `RULES` is the table of moves: only `submit` is open to a non-administrator, for their own entries, and (task 0039) `return`, `approve`, `revert`, `publish` and `lock` are also open to an APPROVER whose scope (`approverScope`) covers every result in the batch (checked inside the transaction, before the state check; out of scope is the one `NOT_AUTHORISED` answer); `unlock` stays an administrator's alone; `approve` refuses your own entries unless self-approval is allowed; `unlock` needs a reason of 5 or more characters and clears the verification token; `publish` mints the token and `contentHash` and is blocked while a scheme approval is pending or rejected. | `results.ts` | Entering results (Slice P2a): `getSheet` and `saveSheet` for one subject, arm and term, `entryOptions`, `armRoster` and `mayEnterResults` (an administrator, or a teacher with a `StaffSubjectAssignment` for exactly that subject and arm). Arithmetic is in hundredths; `saveSheet` is all or nothing (up to 300 rows), refuses results past DRAFT, writes `ResultAudit` rows (ENTERED, EDITED, REMOVED) and locks the scheme and scale on the first save. |
| `scoring.ts` | Pure rules of schemes and grade scales, no database or clock: `toHundredths`, `checkScheme` (1 to 10 uniquely named parts of 1 to 40 characters plus the exam must equal the total exactly), `snapshotScheme` (canonical JSON and SHA-256), `checkBands` (contiguous half-open bands from 0 to 100, at most 12, letters up to 4 characters, remarks up to 40), `gradeFor`, and the limits `MAX_COMPONENTS`, `PART_NAME_MAX` (64) and `DEFAULT_PART_NAMES` that `src/lib/settings/approvals.ts` uses. |
| `sessions.ts` | Academic sessions and terms: `DomainError` (a refusal whose message may be shown to the caller), `createSessionSchema`, `updateSessionSchema`, `listSessions`, `getSession`, `createSession` (label 4 to 30 characters; one to four terms of equal length, three by default and two when the branch name contains "arabic"), `updateSession` and `setCurrentPeriod`. | `staff.ts` | Staff records and teaching assignments (Slice P1c): `staffInput`, `staffPatch`, `listStaff` (live by default, at most 500, search over name, email and phone), `createStaff`, `updateStaff`, `setStaffArchived` (refused while assignments exist), `linkableAccounts`, `linkAccount`, `unlinkAccount` (a sign-in is an active member of the same branch whose role matches the category; the category cannot change while linked), `addAssignment` (the arm's class must study the subject) and `removeAssignment` (a real delete). Audited. |
| `structure-http.ts` | `structureCall(label, run)` turns `ForbiddenError` into 403, `ConflictError` into 409, `DomainError` into 400 and anything else into a logged, fixed 500 ("Something went wrong. Nothing was changed."); `notFound(what)`; `READ_ROLES` (ADMIN, TEACHING_STAFF, NON_TEACHING_STAFF), shared by the academics and staff routes. |
| `structure.ts` | Classes, arms, subjects and "this class studies this subject" for one branch (Slice P1a): zod inputs (names 1 to 60 characters, subject `code` up to 12 characters of letters, digits, dot, dash or underscore, arm capacity 1 to 500), the list, create and update functions, `setOfferings` (replaces the set; live subjects of the same branch only), `resolveArmId` (matches the legacy `className` and `arm` strings, arm defaulting to "Main", to a live arm), `countUnmatchedEnrolments`, `audit`, `ConflictError` and `ForbiddenError`. Archiving frees the name. |

## API routes: Academics (`/api/v1/academics/`)

Classes and arms, subjects, assessment schemes and grade scales, sessions and terms, attendance by arm, result entry, review and history, scheme levels (class, school-wide, teacher) and promotion. Rows follow the file path. "Own branch only" means the route also asks about the branch it acts on (`withBranch`, or `withAuthGated` for promotion), not just "a role in some branch"; "Administrators" is `roles: [ADMIN]` (an ADMIN membership anywhere, or a superadmin).
