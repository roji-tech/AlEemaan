# Sign-in and account — Components

`src/components/auth/` (the forms and panels of sign-in, account recovery, invitations, two-step verification and the account page), `src/components/landing/` (the landing page) and the two forms that sit next to their
page (`/login`, `/setup`).

## `src/components/landing/`

The landing page a signed-out visitor sees at `/` (task 0048).

| File | Description |
| --- | --- |
| `LandingPage.tsx` | Server component: the landing page, built from `brand.landing` (it takes optional props, task 0044 of Octalve Edu: `copy`, `name`, `labels`, `lang`, `dir`, `switchTo`; here `/` passes only `switchTo` (the link to `/ar`) and `/ar` passes all six with the Arabic words, task 0050). AlEemaan's words (task 0049) speak of the school: headline, lead, the cards (the school's four branches, each with a title and a sentence and no icon, since a card's icon is optional), the kinds of people, an OPTIONAL "how it is run" pair that is not drawn when the brand has none (AlEemaan has none), and the closing band). Landmarks `header`, `main` and `footer`; one `h1`, an `h2` per section, an `h3` per item; the header has the product name, the quiet language link when `switchTo` is given (first of the controls, in the page's own reading order), `ThemeToggle` and "Sign in"; the links are `/login` (four times: header, hero, closing band, footer) and the brand's `landing.links` (AlEemaan: "Parent and pupil portal", `/portal`; the first is the hero's quiet button and every one is in the footer). No image, script, font or storage of its own; written on the server, so it reads without JavaScript. The file is code-identical with Octalve Edu's. Rendered by `src/app/page.tsx` for a signed-out visitor and, in Arabic, by `src/app/ar/page.tsx`. Since task 0070 it also takes optional `children` (a product's own sections, drawn before the closing band; Octalve Edu's copy is byte-identical and its `/` gives none); here both pages pass `SchoolInfo`. |
| `SchoolInfo.tsx` | Server component (task 0070): the school's own sections of the landing page, passed through `LandingPage`'s `children` slot on `/` and `/ar`. `SchoolAbout` is the shape of its words (`brand.landing.about`, `landingAr.about`: three programs, four values, the contact heading and sentence and the four labels). Draws "Our programs" and "What we stand for" as cards and lists with an h2 each and an h3 for each item, and "Admissions and contact" only when the profile has at least one of telephone, e-mail, address or website. A telephone is a `tel:` link of its digits, an e-mail a `mailto:` link, a website a link only when it is an `http:` or `https:` address (`websiteHref`, with `rel="noopener noreferrer"`), anything else plain text; the telephone, e-mail and website are drawn left to right (`dir="ltr"`), the address with `dir="auto"`. Reads nothing itself: the page passes it the profile from `getPublicContact()`. |

## Colocated with the page (`src/app/login/`)

| File | Description |
| --- | --- |
| `LoginForm.tsx` | Client component: the sign-in form of `/login`. Posts `{ email, password, remember }` to `/api/v1/auth/login`; when the answer is `mfaRequired` it swaps itself for `MfaStep` (the challenge is held only in memory), otherwise it goes to `/dashboard`. One message for every 401, a 429 pauses the form for 30 seconds (courtesy only), "Keep me signed in" starts unticked. It does not read the `accountThrottled` flag the API returns. |

## Colocated with the page (`src/app/setup/`)

| File | Description |
| --- | --- |
| `SetupWizardForm.tsx` | Client component: the first-run form of `/setup` (props `requiresToken`, `insecureBaseUrl`). Collects the administrator's name, email and password with confirmation, plus the deployment token when the server has `SETUP_TOKEN`; checks length, a letter, a digit, the 72-byte limit and matching passwords in the browser, then posts to `/api/v1/setup` (token sent as `x-setup-token` and in the body). Warns when the instance is not served over HTTPS; success shows a "Setup complete" card linking to `/login`. It signs no one in. |

## `src/components/auth/`

The signed-out screens (sign-in step 2, reset, invitation, email confirmation), the cards of the account page (`/account`) and the small client helpers they share.

| File | Description |
| --- | --- |
| `AcceptInviteForm.tsx` | Client component for `/accept-invite`. Reads the token from the URL fragment (`useFragmentToken`), asks `/api/v1/invitations/preview`, then shows one of: a dead link; "signed in as someone else" with a sign-out button; "an account exists, sign in first" with a link to `/login`; a one-button join for the signed-in invitee; or, for a new address, a name and password form (`checkName`, `checkNewPassword`) posting to `/api/v1/invitations/accept`. A new account is not signed in afterwards. |
| `authChannel.ts` | `broadcastSignOut()` and `onSignOutElsewhere(callback)`: cross-tab sign-out over a same-origin `BroadcastChannel` named `aleemaan-auth`; both do nothing where `BroadcastChannel` does not exist. |
| `AuthShell.tsx` | Layout for the signed-out screens (`/login`, `/setup`, `/forgot-password`, `/reset-password`, `/accept-invite`, `/confirm-email`, `/verify/[token]`): a brand panel (name and copy from `brand`) beside the form on large screens, a compact brand header on phones, and a `ThemeToggle`. The logo (the cap icon and the name), in the panel and in the compact header, is a link to `/` (the start page: the landing page for a signed-out visitor, one press from sign-in; an instance still being set up goes on to the wizard); the panel is `role="none"` with only its grid, headline and copyright `aria-hidden`, because a link cannot sit inside a hidden region. `size` ("sm" or "md") sets the form column width. No `use client` directive. |
| `ChangeEmailPanel.tsx` | Client component: the "Email address" card of `/account` (prop `email`). Three views: idle, a form (new address and current password) and "Check your inbox". Posts to `/api/v1/auth/email-change/request` and shows the same confirmation whether or not the address is taken; maps `INVALID_PASSWORD`, `SAME_EMAIL`, `VALIDATION`, 429 and 401 to messages. The "works once, for an hour" wording is typed in, not derived from a constant. |
| `ChangePasswordForm.tsx` | Client component: the "Password" card of `/account`. Current, new and confirmation fields, the new one checked with `checkNewPassword` before posting to `/api/v1/auth/change-password`; success clears the fields and says the other devices were signed out. Maps `INVALID_CURRENT_PASSWORD`, `VALIDATION`, `SAME_PASSWORD`, 429 and 401. |
| `ConfirmEmailForm.tsx` | Client component for `/confirm-email`. Reads the token from the URL fragment and waits for a click on "Confirm email address" before posting to `/api/v1/auth/email-change/confirm`: it does not act on arrival, because mail scanners open links and would spend the single-use token. Shows done, dead-link and incomplete-link states; success says the person was signed out everywhere. |
| `ForgotPasswordForm.tsx` | Client component for `/forgot-password`: one email field posting to `/api/v1/auth/forgot-password`. The confirmation ("if an account exists...") is shown for any address and states the link lasts `RESET_LINK_MINUTES` (30) minutes; 429 and network failures have their own messages. |
| `MfaStep.tsx` | Client component: sign-in step 2, shown inside `LoginForm` (props `challenge`, `onBack`, `onExpired`). Takes the 6-digit code or, through `FactorModeToggle`, a recovery code and posts it with the challenge to `/api/v1/auth/login/mfa`. `INVALID_CHALLENGE` calls `onExpired`, 429 pauses the form for 30 seconds, 503 says two-step verification is unavailable; success goes to `/dashboard`. |
| `postJson.ts` | Client fetch helpers: `sendJson(path, method, body)`, `getJson(path, signal)` and `sendForm(path, form)` (a multipart POST, for a picture) reduce every outcome (including no network: status 0, code `NETWORK`) to one `Reply` (`ok`, `status`, `code`, `message`, `data`, `meta`, `details`); `problemFor(reply, field)` finds a `body.<field>` problem; shared messages `NETWORK_ERROR`, `GENERIC_ERROR`, `RATE_LIMITED`, `SESSION_ENDED`. Imported by 32 files, 27 of them outside this folder. |
| `ProfileDetails.tsx` | Client component: the "Profile" card of `/account` (props `name`, `email`). Edits the name in place: `checkName` in the browser, then `PATCH /api/v1/account/profile` and `router.refresh()` so the header updates; an unchanged name sends nothing. The email is shown read-only (it changes through `ChangeEmailPanel`). |
| `ResetPasswordForm.tsx` | Client component for `/reset-password`. Reads the token from the URL fragment, checks the new password with `checkNewPassword` and posts `{ token, password }` to `/api/v1/auth/reset-password`. `INVALID_TOKEN` shows a dead-link screen with a link to `/forgot-password`; success says every device was signed out and offers `/login`. |
| `SecondFactorField.tsx` | Shared pieces for typing a second factor: `SecondFactorField` (authenticator code or recovery code input), `FactorModeToggle` (the "use a recovery code instead" switch), `factorPayload(mode, raw)` (`{ code }`, `{ recoveryCode }` or null when mis-shaped, using `normaliseTotpCode` and `normaliseRecoveryCode`) and `FACTOR_FORMAT_ERROR`. Used by `MfaStep` and the turn-off form in `TwoStepPanel`. |
| `SessionRevalidator.tsx` | Client component that renders nothing. Re-runs the server render (`router.refresh()`) when the browser restores a page from the back/forward cache, and sends the tab to `/login` when another tab signs out (`onSignOutElsewhere`). Mounted by `AppShell`. |
| `SessionsPanel.tsx` | Client component: the "Active sessions" card of `/account`. Fetches `GET /api/v1/auth/sessions` in the browser, lists devices with relative times and a "This device" badge, and offers "Sign out" per other device (`/sessions/revoke`) and "Sign out of all other devices" (`/sessions/revoke-others`); a 404 on revoke counts as already gone. |
| `SignOutButton.tsx` | Client component: a "Sign out" button built on `useSignOut` (label hidden on narrow screens, error shown beside it). Nothing imports it: `ProfileMenu` and `MobileNav` in the shell call `useSignOut` directly. |
| `TwoStepPanel.tsx` | Client component: the "Two-step verification" card of `/account` (props `available`, true when `MFA_ENCRYPTION_KEY` is set, `enabled`, `recoveryCodesRemaining`). A state machine: off, password (`/mfa/enroll`), scan (QR drawn in the browser with the `qrcode` package, setup key, `/mfa/confirm`), recovery codes shown once (copy, download, an "I have saved them" tick before Done), on (warns at 2 or fewer codes left), regenerate (`/mfa/recovery-codes`) and turn off (`/mfa/disable`, password plus a factor). Has its own `post` helper rather than `postJson.ts`. |
| `useFragmentToken.ts` | Client hook `useFragmentToken()` returning `{ token, version }`: reads `#token=...` from the URL fragment (never sent to a server, so not in logs or `Referer`), removes it from the address bar with `history.replaceState` and listens for `hashchange`. `token` is `undefined` before the first read and `""` when there was none; `version` rises with each link read so callers can `key` their state on it. Used by the reset, invitation and email-confirmation forms. |
| `useSignOut.ts` | Client hook `useSignOut()` returning `{ signOut, pending, error }`: POSTs `/api/v1/auth/logout`, broadcasts the sign-out to other tabs, then `router.replace("/login")` and `router.refresh()`. On failure it reports an error and leaves the person signed in. Used by `SignOutButton`, `AcceptInviteForm` and the shell's `ProfileMenu` and `MobileNav`. |
