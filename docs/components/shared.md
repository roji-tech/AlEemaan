# Shared — Components

Building blocks used across the app: the form and layout primitives (`ui/`), the app shell and navigation (`shell/`), the service-worker registration (`pwa/`), the
development-only inbox (`dev/`) and the quick-tools drawer (`tools/`).

## `src/components/ui/`

The form fields, buttons, dialog, alert, card, icon set and theme switch that other components build on, styled only with the semantic Tailwind tokens (`bg-surface`, `text-fg`, `bg-brand-strong` and so on) that `src/app/globals.css` maps to CSS variables.

| File | Description |
| --- | --- |
| `Alert.tsx` | `Alert` with `variant` `error`, `warning`, `info` or `success`, optional `title`, `id`, `className`, `announce`. Every variant has an icon as well as colour. `error` and `warning` render `role="alert"`, `info` and `success` render `role="status"`; pass `announce={false}` when the alert sits inside a live region the caller already owns, or it is read twice. |
| `Button.tsx` | `Button` with `variant` `primary` (default), `secondary`, `ghost` or `danger`, and `loading`, which shows a spinner, sets `aria-busy` and disables the button. `type` defaults to `"button"`, so a submit button must pass `type="submit"`. Minimum height 44 px. |
| `Card.tsx` | `Card`: the standard raised surface (a `div` with border, `bg-surface`, `shadow-card` and padding). Passes every `div` attribute through and appends `className`. |
| `CheckboxField.tsx` | `CheckboxField` (`label` plus any `input` attribute except `type`): a real checkbox inside a real `label`. The visible box is drawn in CSS (brand fill when checked, focus ring) over an invisible 44 x 44 px input, and the tick follows the system text colour under `forced-colors`. |
| `Dialog.tsx` | Client component: a modal on the native `<dialog>` (`open`, `onClose`, `title`, `description`, `wide`, `confirmClose`). The children are mounted only while `open`. With `confirmClose` Escape does not close the platform dialog by itself: it is reported through `onClose` and the owner decides (a dialog that may hold unsaved work, task 0084). It does not close on an outside click, so a half-filled form survives a stray tap. A dialog opened inside another (the detail of a question and its approve form) closes only itself: React hands a nested dialog's `close` up to the parent's `onClose`, so the handler ignores any close that did not start at its own dialog. `onClose` is called by the Close button and by the dialog's `close` event (Escape, or the owner setting `open` to false), so keep it idempotent. On open, focus goes to the element marked `data-initial-focus`, otherwise to the first `input`, `select` or `textarea`. |
| `ListToolbar.tsx` | Client component (task 0085, `trailing` slot for the view toggle in task 0089): the toolbar of a list, a search box with a **Filters** button beside it (`aria-expanded`, the number of filters set) that opens and closes a labelled panel of the list's filters (children) and a "Clear filters" button; closing keeps the values. Used by Academics (Classes, Subjects) and Users. |
| `usePagedList.ts` | `usePagedList({ endpoint, key, filters, limit })`: a list from the server a page at a time (the shape in `lib/api/paged.ts`): `items` (null until the first page), `meta`, `page`, `setPage`, `error`, `loading`, `reload`. Goes back to page 1 when a filter changes, ignores an answer that is no longer wanted, and steps back a page when the last row of the last page is removed. Pair with `Pager`. |
| `Toaster.tsx` / `toast-model.ts` | Toasts (task 0096). `ToastProvider` (mounted in the root layout), `useToast()` -> `{ notify, dismiss }`, and `useNotice()`, a drop-in for `useState<Notice>(null)`: with the provider, `setNotice({ variant, text })` shows a toast and `notice` stays null; without it, plain state. Success 5 s, info 6 s, warning 9 s, error 12 s; hover or focus holds; closable; at most four; a repeat replaces the old; errors are `role="alert"`. Classes only (the CSP refuses inline styles). `toast-model.ts` holds the pure rules (`addToast`, `lifetimeMs`, `roleOf`, `MAX_TOASTS`). |
| `Tabs.tsx` | The ARIA tab strip (`Tabs`, `tabId`, `panelId`): Left/Right/Home/End move and select; the owner draws the active panel. |
| `Tabs.tsx` | The ARIA tab strip (`Tabs`, `tabId`, `panelId`): Left/Right/Home/End move and select; the owner draws the active panel. Task 0089: a margin above the strip (`mt-5`, set with `className`), labels that never wrap (the strip scrolls sideways, snaps, fades at the edge that has more and brings the chosen tab into view), tabs at least 44 px high. Academics, Users and the other tab pages use it. |
| `ActionsMenu.tsx` | The three-dots button of a row and its list (task 0100; before, a text button "Actions v"). Icon-only, 44 px, named "Actions for <name>", `aria-expanded`; the list is a popover under the button at every screen size (over it when there is no room below), 14 rem at least, never wider than the screen. Danger entries (`danger: true`) are set apart and red. While open the menu is raised (`z-30`) above everything after it: the buttons of the rows below can no longer be drawn over the list (the bug of 2026-11-18). Task 0111: `action-look.tsx` gives Terminate (and Expel, Withdraw) a red "leaves" icon, not the bin of Remove/Delete; Manage a sliders icon so it is not Edit's pencil; View an eye. |
| `app/globals.css` scrollbars | Task 0111: every scrolling area (page, sidebar, dialogs, tables) has a thin scrollbar, a rounded thumb in the brand green toned with `--line-strong` (`--scroll-thumb`, about 3.2:1 on the canvas in each theme) on a clear track. Standard `scrollbar-width`/`scrollbar-color` for Chrome, Edge and Firefox; WebKit pseudo-elements for Safari, with a hover colour (`--scroll-thumb-hover`). |
| `usePopover.ts` | What every dropdown shares (task 0100): open state, Escape (focus back on the button), a press or focus outside closes, focus goes to the current (`aria-current`) or first item on open, Up/Down/Home/End move, and the list opens upward when there is no room below. Hands the three elements out as callback refs (React's refs lint rule cannot tell a ref object returned from a hook from one read during render). Also `POPOVER_LIST`, `POPOVER_ITEM`, `popoverSide`. |
| `BranchPicker.tsx` | The slim bar "BRANCH: <name> [Switch branch v]". The list it opens is ours (task 0100), not the browser's native select list, which ignored the dark theme (pale grey on white), was narrower than its button and opened over the page: a popover in the page's colours, as wide as its longest name, a tick on the current branch (`aria-current`), keyboard as `usePopover`. One branch: the name alone. |
| `tab-param.ts`, `useTabParam.ts` | The open tab in the address as `?tab=` (task 0100): `pickTab` (a tab the page has, else the fallback; never trusts an unknown value), `withTab` (sets `tab`, keeps other parameters, drops `new` and the older `section`); `useTabParam(ids, fallback)` returns `[active, choose]` like `useState` and rewrites the address with history `replaceState` (no reload, Back leaves the page). Used by Academics, Approvals, Users and Settings. |
| `dialog-title.ts` | `splitTitle`: a dialog title that is an action and a name ("Edit Aluko Fuad") is drawn with the action in the quiet colour and the name in the accent. Same text, so the accessible name is unchanged. Only a known action followed by a capital letter or digit is split ("Edit arm Main" is left whole). |
| `Pager.tsx` | `Pager` (task 0089): "Showing 13 to 24 of 57" (`total` + `size`), Previous / Next, numbered pages from `sm` up (the first, the last, the current page and its neighbours, with gaps), "Page 2 of 5" on a phone, `aria-current="page"`, an optional "Per page" choice (`sizes` + `onSize`); nothing when there is one page unless a size choice is offered. Re-exports `paginate(items, page, size)`. |
| `collection-model.ts` | The pure rules of the list/grid kit, tested without a browser: `SIZES` (list 10/25/50, grid 12/24/48), `defaultSize`, `parseChoice` / `storeChoice` (the remembered choice, field-by-field fallback), `sizeAfterViewChange`, `pageAfterResize` (the first visible item stays on screen), `pageRange`, `pageList`, `paginate`. |
| `useCollectionView.ts` | `useCollectionView(key, { defaultView, defaultSize?, page?, onPage? })` -> `{ view, size, setView, setSize, sizes }`: the list's view and page size, remembered in `localStorage` (`aleemaan.view.<key>`) through `useSyncExternalStore`; a convenience of the browser, never data. |
| `ViewToggle.tsx` | The List / Grid buttons (`aria-pressed`, 44 px targets); put it in `ListToolbar`'s `trailing`. |
| `Collection.tsx` | `Collection` (the frame: loading, empty, "nothing matches" with Clear filters, else the list or grid, a container-query layout) and `Item` (one record described by `title`, `subtitle`, `leading`, `badges`, `facts`, `children`, `href`, `actions`, `menu`; drawn as a card in a grid and a row in a list), with `ItemTile`, `ItemInitials`. Example: `components/academics/ClassesPanel.tsx`. |
| `icons.tsx` | 41 inline SVG icon components (`EyeIcon`, `SpinnerIcon`, `AlertTriangleIcon`, `HomeIcon`, `UsersIcon`, and so on), with no icon library. Each takes SVG props, defaults to 20 px, strokes in `currentColor` and is `aria-hidden`, so the meaning must come from adjacent text or an `aria-label` on the control. `CheckCircle2Icon` is exported but nothing imports it. |
| `info-tips.ts` | The words of every info icon (task 0054): `INFO_TIPS`, a typed object from a key (`academics.schemes`, `students.show`, ...) to one or two short sentences, and `InfoTipKey`. A screen names a key and cannot invent text. `tests/unit/info-tips.spec.ts` holds every sentence to the same rules (20 to 200 characters, ends in a full stop, at most two sentences, no two alike, none unused). |
| `InfoTip.tsx` | Client component: `InfoTip` (`tip`, an `InfoTipKey`; `className`), a 16 px "i" button that shows the tip's words in a `role="tooltip"` popover. Opens on hover (150 ms), on keyboard focus and on click or tap; closes on Escape (wherever the focus is, and cancelled so a native `<dialog>` stays open for that press), on a click elsewhere, on blur and when another opens. It is always a sibling of what it explains. Its name is the fixed "More information" (a name holding the topic would collide, by substring, with the label or button beside it in `getByLabel` and `getByRole`); tests find it by `data-info-tip`. The popover is absolute (no layout shift) and placed below or above the icon, kept inside the window. 24 px touch target (WCAG 2.2 AA, 2.5.8) as an invisible extension, and no larger: a bigger invisible area sits on top of a control placed a few pixels away and takes its taps (task 0056). `print:hidden`. |
| `PasswordField.tsx` | Client component: a `TextField` of type `password` with a show/hide button (`aria-pressed`, `aria-controls`, label "Show password" / "Hide password"). Takes the `TextField` props except `type` and `trailing`; always sets `autoCapitalize="none"` and `spellCheck={false}`, which the caller cannot override. |
| `SelectField.tsx` | `SelectField`: a labelled native `<select>` wired like `TextField` (`label`, `options` as `{ value, label }[]`, `hint`, `error`, `hideLabel`, `info`). `hideLabel` keeps the label as the accessible name but hides it, for filter bars. `info` (an `InfoTipKey`, task 0054) puts an info icon beside the label, never inside it; it is ignored with `hideLabel`. A placeholder is an ordinary option with an empty `value`. |
| `TextAreaField.tsx` | `TextAreaField`: a labelled `<textarea>` wired exactly like `TextField` (`label`, `hint`, `error`; `rows`, `maxLength` and the rest pass through). |
| `TextField.tsx` | `TextField`: a labelled `<input>` with the accessibility wiring done once: a real `label`, `hint` and `error` linked through `aria-describedby`, `aria-invalid` on error. Task 0044 adds `hideLabel` (the label stays the accessible name; used by a row of a grid). Task 0073 adds `info` (an `InfoTipKey`): an info icon beside the label, a sibling of it and never inside it, so the accessible name is the label alone; ignored with `hideLabel`. |
| `ThemeProvider.tsx` | Client component: `ThemeProvider` (`initialTheme`, read from the `theme` cookie by the root layout) and `useTheme()` returning `{ theme, toggleTheme }`, which throws outside the provider. `toggleTheme` sets `data-theme` on `<html>` and writes the `theme` cookie (path `/`, one year, `SameSite=Lax`, `Secure` only on https). No inline script is involved. |
| `ThemeToggle.tsx` | Client component: the icon button that calls `toggleTheme`. Its accessible name says what will happen ("Switch to light theme" / "Switch to dark theme") and the icon shows the theme you would switch to. Used by `AppShell` and `AuthShell`. |

## `src/components/shell/`

The frame around every signed-in page (the `(app)` route group): sidebar, top bar, phone tab bar, and the navigation list they are all built from.

| File | Description |
| --- | --- |
| `AppShell.tsx` | The frame the `(app)` layout wraps every signed-in page in (`user: ShellUser` with `name`, `email`, `roleLabel`, `isAdmin`, `isSuperAdmin`, `isTeacher`, `isStaff`). From `lg` up: a 248 px sidebar (`SidebarFrame`: brand, `SidebarNav` in foldable sections, the signed-in person pinned at its foot) that folds to a 64 px rail of icons (`SidebarProvider` is the root element and carries `data-sidebar`, which the page padding follows), and a 60 px top bar (`Breadcrumb`, `ThemeToggle`, `ProfileMenu`). Below `lg`: `MobileNav`. Also mounts `SessionRevalidator` and `QuickToolsTrigger`, and puts a skip link to `#main` first. It takes the two remembered sidebar choices (`sidebarCollapsed`, `foldedSections`) from the `(app)` layout, which reads them from cookies. Sidebar, top bar and tab bar are hidden when printing. It only displays who is signed in; every page still checks the session itself. `user.pages` (`PageOverrides`, from `session.user.pages`) is passed on to `SidebarNav` and `MobileNav`. |
| `Breadcrumb.tsx` | Client component: the two-level crumb in the top bar, shown from `lg` up. The first crumb is the `section` prop; the second is `PAGE_LABELS[pathname]`, an exact match, so a path that is not listed (including any sub-path of a listed page) shows only the section. `aria-current="page"` marks the last crumb. |
| `MobileNav.tsx` | Client component: phone navigation below `lg`. A floating bottom tab bar of the `navFor` entries that are not `inMore`, plus a "More" button that opens a native modal `<dialog>` sheet with the `inMore` entries, any entry without an `href` (with a Soon tag), Profile (`/account`) and Sign out (`useSignOut`, error shown inline). The order of `NAV` itself is unchanged, because the phone tab bar comes from it. `navFor(isAdmin, isSuperAdmin, isTeacher, isStaff, pages)` filters it; the flags only hide links, the page and API enforce access. Also `PAGE_LABELS`, `isActive`, `FOCUS_RING` and `initialsOf`. `navFor` takes a fifth argument `pages` (`PageOverrides`: `included` and `excluded`, keyed by `href`; the role decides first, `excluded` removes an entry and wins over `included`, `included` adds an entry the role does not give but never an administrators' or a superadmin's page); `QUESTION_BANK_HREF` and `NO_PAGE_OVERRIDES` are exported. |
| `PageHeader.tsx` | `PageHeader` (`title`, optional `description` and `actions`): the page's one `<h1>`, a one-line description under it and an action area on the right (stacked below `sm`). Section headings below it should be `<h2>`. Used by the `(app)` pages. |

A disclosure, not an ARIA menu, holding Profile (`/account`), Sign out (`useSignOut`, error shown inline) and, when `isAdmin`, a non-link "Settings" entry with a Soon tag, although `/settings` is built and is in `NAV` for superadmins. Choosing goes to the page AND its `?tab=`. Empty, it offers the last five chosen (only ids, in `localStorage`) and a few common questions. Everything is on the device: no request is made while typing. The index is `lib/search/destinations.ts`, matching `lib/search/match.ts`, who sees what `lib/search/visible.ts` (the sidebar's own `navFor`, so a person never finds a page they cannot open; courtesy, not security: every page and API still refuses whoever it refuses), the tab ids `lib/search/tab-ids.ts`; `tests/unit/search.spec.ts` fails when a tab exists that the index cannot reach or the index names a tab that is gone. |
| `SidebarNav.tsx` | Client component: the desktop sidebar list built from `navFor(isAdmin, isSuperAdmin, isTeacher, isStaff, pages)` and grouped by `groupNav`. ## `src/components/pwa/`

Offline support: the registration of the service worker and the offline indicator.

| File | Description |
| --- | --- |
| `ServiceWorkerRegister.tsx` | Client component, mounted once by the root layout so every page has it, the sign-in pages and the website included (task 0104; it used to be inside the app shell only, so the pages people install from never registered the worker): registers `/sw.js` (`public/sw.js`) on mount, ignoring a failed registration, and shows a fixed "Offline Mode — Cached resources available" status pill while `navigator.onLine` is false. It starts as online and reads `navigator.onLine` only after mount, so the server HTML never contains the pill. The worker is network-first for page navigations with the cached `/offline` page as the fallback, cache-first for images, fonts and styles, and ignores `/api/` and non-GET requests. |
| `InstallApp.tsx` | Client component (task 0104): "Install the app" where the browser has offered the install (a button that calls the kept `beforeinstallprompt`), one line saying Share, then Add to Home Screen on an iPhone or iPad, nothing when the app is installed or the browser offers no install. Rendered under the sign-in forms (`/login`, `/portal`), in the account menu and in the phone's More sheet. The state is in `lib/pwa/install.ts`, which `ServiceWorkerRegister` imports so the one early event is never missed; `lib/pwa/manifest.ts` is the web app manifest each address is given (`app/manifest.ts` reads the host). |

| File | Description |
