# School app — Pages

The signed-in school app: every page under the `(app)` route group of `src/app/`. They share one layout (`(app)/layout.tsx`: the session check, the shell with the sidebar and the
phone tab bar) and are listed here in the order of the navigation (`src/components/shell/nav.ts`, which is the single source of truth for who sees which entry). Hiding an entry is
a courtesy: each page and each API route behind it enforces its own access. The route has no route-group parentheses.

## Overview and account

| Route | File | Description |
| --- | --- | --- |
| `layout (app shell)` | `(app)/layout.tsx` | Layout of the `(app)` route group: every signed-in page renders inside `AppShell`. It calls `requirePageSession()` (signed out goes to `/login`) only to show who is signed in and to pass `name`, `email`, `roleLabel`, `isAdmin`, `isSuperAdmin` and `isTeacher` (any active `TEACHING_STAFF` membership) to the shell. It is display only: a layout is not re-rendered when moving between its pages, so each page repeats the check itself. |
| `/dashboard` | `(app)/dashboard/page.tsx` | The Overview page; anyone signed in (`NAV` "Overview" has no flag), signed out goes to `/login`. A non-administrator gets "Welcome, name" and one tile per active membership (branch name and role label), or a note to ask an administrator for a branch. An administrator (any branch, or superadmin) gets three tiles (branch count, people with an active membership, own role) and up to six branches, oldest first, with active member counts. These counts are school-wide, not narrowed to the viewer's branches, and the "Manage branches" link is shown to every administrator although `/branches` is superadmin only. |
| `/account` | `(app)/account/page.tsx` | Anyone signed in (reached from the profile menu's "Profile" item; it is not in `NAV`); signed out goes to `/login` through `requirePageSession`. Server page (`force-dynamic`) that stacks cards: Profile (`ProfileDetails`, editable name), Your access (the caller's active memberships: branch name and role label), Email address (`ChangeEmailPanel`), Password (`ChangePasswordForm`), Two-step verification (`TwoStepPanel`, fed by `mfaConfigured()` and `getMfaStatus`) and Active sessions (`SessionsPanel`). |

## School set-up

| Route | File | Description |
| --- | --- | --- |
| `/branches` | `(app)/branches/page.tsx` | Superadmins only (`NAV`: `superAdminOnly`). Anyone else signed in sees an inline "You don't have access to this page" alert with a "Back to overview" link to `/dashboard` (no redirect, and no branch data is fetched for them); signed out goes to `/login`. A superadmin gets every branch, oldest first, with its count of active (not deactivated) memberships, and the colocated `BranchesView` renders them. |
| `/settings` | `(app)/settings/page.tsx` | Superadmins only (`NAV` `superAdminOnly`). Anyone else signed in sees an inline "You don't have access to this page" alert with a "Back to overview" link to `/dashboard`, and nothing is loaded; signed out goes to `/login`. A superadmin gets the school profile (`getSchoolSettings`, unset fields as empty strings), every branch, and every non-archived academic session with its non-archived periods (`listSessions`, dates as `YYYY-MM-DD`), rendered by the colocated `SettingsView`. |
| `/academics` | `(app)/academics/page.tsx` | Classes and subjects, assessment schemes and grade scales, staff and promotion, as four tabs (`AcademicsSections`). Anyone signed in may load it (signed out: redirect to `/login`); the nav lists it for administrators only (`adminOnly`) but the page does not check the role. It offers the branches where the person holds a staff role (a superadmin: all) and sets `canEdit` only where they administer the branch, so a teacher who types the URL gets a read-only view. With no staff branch it shows "You don't belong to a branch with staff access yet." |
| `/users` | `(app)/users/page.tsx` | Administrators (an `ADMIN` membership in any branch, or a superadmin; `NAV` `adminOnly`). Anyone else signed in sees an inline "You don't have access to this page" alert with a "Back to overview" link to `/dashboard`, and no people are fetched; signed out goes to `/login`. An administrator gets the branches they may pick (all for a superadmin, their own `ADMIN` branches otherwise, from `adminScope`) and the `UsersPanel`, given `currentUserId` and `isSuperAdmin`. |
| `/approvals` | `(app)/approvals/page.tsx` | Approvals and rules: requests waiting for a decision, report-card layout, what the public verification page shows, and (superadmin only) who may approve their own marks. For administrators (`adminOnly` in `NAV`); anyone else who types the address sees an inline "Only administrators can open this page." with no redirect (a signed-out visitor goes to `/login`). Lists every branch where the caller holds a staff role, each flagged `canEdit` only when they administer it, and renders `ApprovalsSections`. `force-dynamic`. |
| `/question-bank` | `(app)/question-bank/page.tsx` | Administrators (an `ADMIN` membership in any branch, or a superadmin; `NAV` `adminOnly`). Anyone else signed in sees a "Only administrators can open this page." alert with no link; signed out goes to `/login`. An administrator gets the branches `branchIdsFor` returns (all for a superadmin, otherwise those where they hold any staff role), by name, each flagged `canEdit` only where `mayAdminister` is true, rendered by `QuestionBankSections`. Slice 1 only: reviewers and settings; the header text differs for a superadmin and a branch administrator. |

## Teaching and records

| Route | File | Description |
| --- | --- | --- |
| `/students` | `(app)/students/page.tsx` | The pupil register of each branch (`StudentsPanel`): search, register, edit, archive and restore, CSV import. Anyone signed in may load it (signed out: redirect to `/login`); the nav shows it to administrators and teachers (`staffOnly`). It offers the branches where the person holds a staff role (a superadmin: all) and sets `canEdit` only where they administer the branch; the students API decides every read and change. With no staff branch it shows "You don't belong to a branch with staff access yet." |
| `/lms` | `(app)/lms/page.tsx` | Coursework page (assignments, study materials, quizzes). Its `NAV` entry is `staffOnly` (administrators and teachers) but the page only needs a session, so a student or parent who types `/lms` gets it with no staff buttons; a signed-out visitor goes to `/login`. Branches: all for a superadmin, otherwise those of the caller's memberships. Builds `rolesByBranch` (the role held in each branch, ADMIN everywhere for a superadmin) and renders `LmsPanel`, or a notice when there is no branch. `force-dynamic`. |
| `/attendance` | `(app)/attendance/page.tsx` | The daily roll call (`AttendancePanel`). Anyone signed in may load it (signed out: redirect to `/login`); the nav shows it to administrators and teachers (`staffOnly`). It offers the branches where the person holds a staff role (a superadmin: all) and passes `isAdmin` (administers at least one branch, or superadmin), which adds the "Manage Permissions" dialog. Which arms a person may take is decided by the attendance API, not here. With no staff branch it shows "You don't belong to a branch with staff access yet." |
| `/results` | `(app)/results/page.tsx` | Entering, reviewing and publishing marks and reading report cards, as tabs (`ResultsSections`). Anyone signed in may load it (signed out: redirect to `/login`); the nav shows it to administrators and teachers (`staffOnly`). It offers the branches where the person holds a staff role (a superadmin: all), marks each `canEdit` where they administer it, and passes `isAdmin` (administers any branch, or superadmin), which adds the Review tab. The header is hidden when printing. With no staff branch it shows "You don't belong to a branch with staff access yet." |
| `/timetable` | `(app)/timetable/page.tsx` | The weekly timetable (`TimetablePanel`, "Timetable & Scheduling"). Anyone signed in may load it (signed out: redirect to `/login`); the nav shows it to administrators and teachers (`staffOnly`). It offers the branches where the person holds a staff role (a superadmin: all) and passes `isAdmin` (administers at least one branch, or superadmin) as the only edit switch, so the controls are not decided per branch; the timetable API refuses a change in a branch the person does not administer. With no staff branch it shows "You don't belong to a branch with timetable access yet." |

## Communication and money

| Route | File | Description |
| --- | --- | --- |
| `/announcements` | `(app)/announcements/page.tsx` | Announcements and broadcasts feed. Open to anyone signed in: no role check here and no flag on its `NAV` entry; a signed-out visitor goes to `/login` (`requirePageSession`). Loads every branch's id and name for the filter and renders `AnnouncementsPanel`; `canCreate` is true for administrators, teachers and superadmins, and `userBranchId` is the first membership's branch. `force-dynamic`. |
| `/communication` | `(app)/communication/page.tsx` | Communication page: broadcasts, dispatch logs and notification templates. For administrators (`adminOnly` in `NAV`); anyone else who types the address sees an inline "Only administrators can open this page." with no redirect (a signed-out visitor goes to `/login`). Branches: all for a superadmin, otherwise those of the caller's memberships. Renders `CommunicationPanel`, or a notice when the caller has no branch. `force-dynamic`. |
| `/finance` | `(app)/finance/page.tsx` | Finance and fee invoicing page. For administrators (`adminOnly` in `NAV`); anyone else who types the address sees an inline "You don't have access to this page" card with a link back to `/dashboard`, with no redirect (a signed-out visitor goes to `/login`). Branches: all for a superadmin, otherwise the ones the caller administers (`adminScope`). Renders `FinancePanel`, or a notice when there is no branch. `force-dynamic`. |
