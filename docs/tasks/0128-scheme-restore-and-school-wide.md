# 0128: restore archived schemes and scales, edit the school-wide default, and make the school-wide scheme usable

- **Status:** In Progress: built; tests passing except four old specs (see Tests). No migration.

The maintainer (2026-11-26, Academics > Assessment and grading): "there is no way to unarchive schemas", "there's no way to edit School-wide default", and then, with screenshots, "why am I still getting an error even though I have a school-wide default?" (marks entry said "Set up an assessment scheme for this branch first").

## What I found
- **Archived schemes and scales were hidden with no way back.** The API already returned them with `includeArchived=true` and the list route is there; the screen never asked, and no restore existed.
- **The school-wide default had no Edit.** The list showed a name and a sum, and one button, "New school-wide scheme".
- **The school-wide scheme is never read by marks entry.** `loadContext` takes the class's own scheme, then its result template's, then the branch's own default (`hosted: false`); `resolveEffectiveScheme`, which ends at the school-wide scheme, has no caller outside its own file. The Scheme levels note said "then the school-wide one": it was not true. It cannot simply be read, either: a result names its own branch's scheme through a composite key (`branchId`, `schemeId`), so a scheme hosted by one branch cannot be a result's scheme in another.

## Decisions
1. **Restore** for schemes (`POST /assessment-schemes/[id]/restore`) and grade scales (`POST /grade-scales/[id]/restore`): safe to repeat, audited, checked under the same lock as every scheme write. Refused in words when: a newer version replaced it (the newer one is the live one; the old one stays archived for good, which `liveScheme` relies on), another live scheme/scale has its name, another live scheme holds its place (the branch default, or that class's scheme), or its class is archived. A scale comes back never as the default.
2. **Edit the school-wide default** (`PATCH /schemes/global/[id]`, superadmin only): the same rule as creating (parts and exam add up to exactly 100), making it the default clears the previous default, refused when archived or locked, audited with before and after. It cannot be locked in practice (no result uses it), but the check stays.
3. **Make the school-wide scheme usable: copy it.** `POST /assessment-schemes/from-school-wide { branchId }` (administrators of the branch) copies the school-wide default into the branch as an ordinary default scheme (editable until a result uses it, then versioned), audited; 409 when the branch already has a default or the school has none. A copy, not a live link, because of the composite key above and because a later edit of the school-wide scheme must never change marks already entered. The screen shows "Use the school-wide scheme" while the branch has no default of its own. Auto-copying at marks entry was not chosen: a write inside a read path, and a branch would silently get a structure nobody chose.
4. **Delete a scheme that is connected to nothing** (the maintainer, mid-task: "if I create a new schema and it is not connected to anything, I should be able to delete it"). `DELETE /assessment-schemes/[id]` (administrators of its branch): removes the scheme and its parts for good, audited with what it was (`ASSESSMENT_SCHEME_DELETED`). "Connected" means: marks were entered against it (locked, or a result names it), a report-card template uses it, it is a school-wide or a teacher's own scheme (a level row), a teacher draft was approved into it, or it is part of a version history (an older or newer version exists). Each is a 409 with the reason and archiving stays the way out; nothing is removed on a refusal. A class's own scheme with none of those can be deleted (the class stays and falls back to its template or the branch default). Archived ones can be deleted too. Done under the same lock as every scheme write; `lockedAt: null` repeats in the delete, and the foreign key from `Result` is the last guard, so a used scheme cannot be removed even by a race. The screen offers Delete (with a confirmation naming the scheme) on a scheme that is not locked, not made for a template or the school-wide level, and not in a version history; the server decides and its reason shows in the dialog. Grade scales are not covered (only schemes were asked for).
5. **Honest wording.** The Scheme levels note and the checkbox label no longer promise a fallback that does not exist; the marks-entry error says to use the copy button; a scheme made for a template or the school-wide scheme is no longer labelled "Branch default" in the list.

## Not done
Applying a changed school-wide scheme to branches that already copied it (each branch's copy is its own; editing it is the branch's choice, and a locked one is versioned); copying to every branch at once for a superadmin.
